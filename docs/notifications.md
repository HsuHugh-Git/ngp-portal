# 申請中心通知與催簽規則（草案）

詞彙見 [CONTEXT.md](../CONTEXT.md)，進度與流轉見 [data-model.md](data-model.md)。

## 1. 管道

第一版**只用 Outlook 信件**，以 Microsoft Graph `sendMail` 從共用信箱寄出（應用程式權限 Mail.Send，由 IT 限制只能代表該共用信箱）。信中附連結，點進申請中心操作。Teams 通知列為第二期（需開發並上架 Teams 應用程式，要實測）。

## 2. 事件與收件人（立即通知）

| 事件 | 收件人 | 內容重點 |
| --- | --- | --- |
| 送出成功 | 申請人 | 申請編號、類別、目前進度 |
| 進入待簽核 | 核准人 | 申請人、類別、摘要、連結 |
| 進入待指定核准人 | IT | 申請編號、申請人、為何找不到核准人 |
| 核准 | 申請人、IT | 已核准，進入待處理 |
| 退回補件 | 申請人 | 核准人意見、修改重送連結 |
| 否決 | 申請人 | 核准人意見，說明需另開新申請 |
| 進入待處理 | IT | 新申請待接手 |
| IT 開始處理／補問 | 申請人 | 進度變更，補問時含問題內容 |
| 申請人回覆補問 | 負責的 IT | 申請人回覆內容 |
| 結案 | 申請人 | 結案結果與說明 |
| IT 重新分類為需簽核 | 申請人、核准人 | 說明因分類變更需補簽 |

## 3. 催簽規則

- 對象：處於**待簽核**的申請，提醒其核准人。
- 頻率：**每天提醒到簽為止**。
- 形式：**每位核准人每天一封彙整信**，列出該核准人所有待簽核申請（編號、申請人、類別、已等待天數），每筆附連結。新進入待簽核的申請仍另外立即寄一封通知。
- 日期：只在**工作日**寄出，固定上午時間；需要一份可由 IT 維護的假日表（含補班）。
- 停止：核准、退回補件、否決、取消、改派核准人後，原核准人不再收到該筆提醒；改派後新核准人從當天重新計算。
- 逾期：等待超過 N 個工作日（預設 5，可在後台調整）時，彙整信標示為逾期，並另外通知 IT 與申請人一次。**不自動升級給上層主管**。

## 4. 規則

- 彙整信沒有待簽核項目時**不寄**。
- 同一事件不重複寄：以申請、事件類型、時間為去重鍵，避免重新部署或重試造成重複信件。
- 信件寄送失敗時記錄並重試，不影響申請本身的進度。

## 5. 待確認

- 共用信箱名稱與寄件人顯示名稱（由 IT 建立）。
- IT 通知的收件人：IT 群組信箱，還是指定的值班人員。
- 假日表：資料倉儲已有 `mart_hr.tw_public_holidays`，優先沿用，需確認是否含補班日及年度更新由誰負責。
- 彙整信寄出時間（建議上午 9:00）。
- 逾期天數預設 5 個工作日是否合適。
- 每天提醒是否讓主管反感，上線後看簽核時效與主管反應再調整（已記錄：使用者選擇每天提醒到簽為止）。
